# 09. Hardware Components

## You will learn

- how a **processor** runs a program (fetch, decode, execute) and what an **instruction set architecture** (ISA) is
- the three architectures you will meet: **x86-64**, **ARM** (`aarch64`) and **RISC-V**, the difference between **CISC** and **RISC**, and why a program compiled for one does not run on another (`uname -m`, `file`, `Exec format error`)
- what **cores**, **hardware threads** and **hybrid** CPUs are, and how the **memory hierarchy** (registers, caches, RAM, storage) works
- what a **motherboard** holds and what a **System on a Chip** (SoC) is, and the trade-offs between a PC and an SoC (upgrades, power, **unified memory**)
- what the **northbridge** and the **southbridge** are, why the northbridge now lives inside the CPU package (Intel System Agent / SoC tile, AMD I/O die), what the **chipset** does today and why the devices behind it share one link (`lspci`)
- how **storage** works: **HDD** and **SSD**, the **SATA**, **NVMe** and **M.2** interfaces, TB vs GiB, and how Linux names disks (`/dev/sda`, `/dev/nvme0n1`, `lsblk`)
- how the parts **communicate**: the map of the links in a PC, why links are serial, how to compute the speed of a link (lanes, **bits vs bytes**), **PCIe**, **USB** (USB-C is a shape, not a speed), display and network links, and the small buses (I²C, SPI, UART) (`lsusb -t`)
- what **coprocessors** are for: the **GPU** (integrated or dedicated), the **NPU** and the media and security engines, and how Linux shows them (`/dev/dri`, `/dev/accel`)
- how to **inspect** the hardware (`lshw`, `lscpu`, `lspci`, `lsusb`, `lsblk`, `free`) and **measure** its performance (`top`, `dd`, `vmstat`)
