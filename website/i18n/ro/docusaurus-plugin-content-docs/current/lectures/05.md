# 05. Utilizatori și permisiuni

## Veți învăța {/* #you-will-learn */}

- ce este un **utilizator** pentru kernel: doar un număr, **UID**-ul, cu care este etichetat fiecare proces, și cum se împart UID-urile între `root`, utilizatorii de sistem și utilizatorii obișnuiți
- cum funcționează baza de date locală a utilizatorilor (`/etc/passwd`), cum află programele numele corespunzător unui UID prin **biblioteca C** (`getpwuid()`, `getpwnam()`) și de ce, în scripturi, este bine să folosiți `getent` în loc să citiți fișierul cu `grep` sau `cut`
- cum sunt stocate local parolele: se păstrează doar un **hash cu salt**, în `/etc/shadow`, fișier pe care îl poate citi doar `root`
- ce sunt **grupurile** (`/etc/group`) și cum dau drepturi mai multor utilizatori deodată
- ce se întâmplă când vă **autentificați** (`getty`, `login`), cum primește un proces eticheta unui utilizator și cum află biblioteca C, din `/etc/nsswitch.conf`, unde sunt păstrați utilizatorii: în fișiere locale sau pe un server din rețea
- cine este utilizatorul **`root`**: utilizatorul cu UID-ul `0`, pentru care kernelul sare peste majoritatea verificărilor; numele lui nu contează
- cum deveniți `root`: de ce **`sudo`** (cu parola voastră, cu reguli în `/etc/sudoers` și cu jurnal) este mai bun decât **`su`** și de ce `sudo echo ... >> fișier` nu funcționează
- cum funcționează **permisiunile fișierelor**: proprietarul, grupul și ceilalți, drepturile `r`, `w` și `x` pentru fișiere și pentru directoare (un director este o listă de nume), care dintre seturi se aplică și cum le modificați cu `chmod`, `umask`, `chown` și `chgrp`
- ce sunt **permisiunile speciale** (`setuid`, `setgid` și bitul sticky) și de ce nu este bine să setați `+s` pe propriile programe
- de ce nu vă puteți baza pe **prompt** ca să aflați cine sunteți și cum îl întrebați pe kernel cu `whoami` și `id`
