09. Network Infrastructure

In the eighth lab you wrote shell scripts. In this lab you will look at how your computer talks to other computers. You will first see what a network is and its layers, then the network cards and their MAC addresses, the IP address and the mask, the neighbors, the routing table and the default gateway, the names of DNS and the settings that DHCP gives. You will test the network with ping and traceroute, build a small network of containers with Podman, find the ports of its programs, get an address with dhclient, and watch the packets with tcpdump.

The most important idea of this lab is that a packet carries an address for each layer: the MAC address finds the card in the local network, the IP address finds the computer across the networks, and the port finds the program. A computer needs only an IP address with its mask, a default gateway and a DNS server, and DHCP gives it all three.

Objectives​

  • Understand what a network, a packet, a switch and a router are, and the address that each layer uses
  • List the network cards and their MAC addresses with ip link and nmcli
  • Print only one value of the output of a command (a MAC address, an IP address) with awk and cut
  • Find the IP addresses and the masks of a computer with ip address, compute the network of an address, and tell private, public and special addresses apart
  • Test if a computer answers with ping, and understand why it fails
  • Find the MAC addresses of the neighbors with ip neigh
  • Read the routing table with ip route and ip route get, find the default gateway, and the routers on the way with traceroute
  • Turn a name into an IP address with host, and find the DNS server of a computer with resolvectl
  • Find what a computer received from DHCP with nmcli, and ask a DHCP server for an address with dhclient
  • Run containers with podman, and inspect their network from inside and from outside
  • List the TCP and UDP ports that wait for connections, and their programs, with ss
  • Capture packets with tcpdump, choosing them with filters
  • Find why a computer has no Internet, checking the layers from the bottom up

What Is a Network​

A network is a group of computers connected so that they can send data to each other. The data travels in packets: small blocks of bytes (at most about 1500), each with the address of the computer that sent it and of the one that must receive it. Think of a long story sent by post as many letters, each in its own envelope.

DeviceWhat it does
network cardconnects a computer to a network, with a cable or with radio waves (Wi-Fi)
switchconnects the computers of one local network (the lab room) with cables
routerconnects two or more networks, and forwards the packets from one to the other
a home routera switch, a Wi-Fi access point and a router in one box
note

The Internet is a network of networks, joined by routers.

A server is a program that waits for requests (a web server); a client is a program that sends them (the browser).

The Layers​

Sending data is split into layers. Each layer solves one problem, has its own kind of address, and uses the layer below it:

LayerThe question it answersAddressExample
5. applicationwhat does the program want?a nameupb.ro
4. transportwhich program, on that computer?a port443
3. networkwhich computer, across all networks?an IP address10.41.1.27
2. linkwhich card, in the local network?a MAC address8c:16:45:a2:3b:91
1. physicalhow do the bits travel?none: a cable or radio waves

The card does not send the packet alone: it puts it inside a frame, which adds the MAC addresses of the card that sends it and of the card that must receive it. A frame travels only inside one local network. Think of a letter put in a second envelope, addressed only to the next stop.

This lab goes through the layers from the bottom up: the network cards and their MAC addresses (link), the IP addresses and the routes (network), the ports (transport), and DNS (application).

Network Cards​

An Ethernet card uses a cable, a Wi-Fi card radio waves. Each frame has the MAC address of the card that sent it and of the card that must receive it.

A MAC address has 48 bits, written as 6 bytes in hexadecimal: 8c:16:45:a2:3b:91. The first 3 bytes name the manufacturer. It makes sense only in the local network: the switch uses it to send each frame only on the cable of its card. A frame sent to ff:ff:ff:ff:ff:ff, the broadcast address, reaches every card of the network.

Network Interfaces: ip link​

Linux names each card a network interface:

IP Addresses​

To reach a computer in another network, each computer also has an IP address: 32 bits, written as 4 numbers from 0 to 255, such as 10.41.1.27. Think of a postal address: the street is the network, the number is the computer on that street.

Addresses and Masks: ip address​

The mask, written after a /, says how many bits from the left name the network: in 10.41.1.27/24, the network is 10.41.1.0/24, and the last 8 bits (27) name the computer. Computers of the same network talk directly; for any other network, they need a router.

[student@fedora ~]$ ip -br address
lo               UNKNOWN        127.0.0.1/8 ::1/128
enp3s0           UP             10.41.1.27/24 fe80::6a1c:3e0f:7d24:9b11/64
[student@fedora ~]$ ip address show enp3s0

  • inet6 is an IPv6 address: 128 bits, in hexadecimal. This lab uses IPv4, and only looks at the fe80::... address that every card gives itself.

Computing the Network​

The First Steps use only /24, /16 and /8, where the mask ends at a byte. The exercises at home and the exam also use masks that end inside a byte, such as /26: write that byte in binary, keep the bits of the network, and set the other bits to 0 for the network and to 1 for the broadcast. The addresses in between are for the computers: with n bits for the computer, there are 2ⁿ - 2 of them.

Private Addresses and NAT​

A home or a lab gets a single public address from its Internet provider. The computers inside use private addresses, and the router replaces the source address of every packet that goes out with its public address, then changes the replies back. This is NAT (Network Address Translation). Think of a company with one phone number: the receptionist knows which desk each call is for.

[student@fedora ~]$ curl -s https://ifconfig.me; echo
141.85.227.12
  • ifconfig.me answers with the address it sees: 141.85.227.12, not 10.41.1.27, because a router did NAT.

Neighbors: ip neigh​

To send a packet to 10.41.1.28, in its own network, the computer needs the MAC address of that card. It asks the whole network with a broadcast, "who has 10.41.1.28?", and the card that has it answers. This is ARP. The answers are kept in the neighbor table:

[student@fedora ~]$ ip neigh
10.41.1.1 dev enp3s0 lladdr 70:b5:e8:2d:91:4c REACHABLE
10.41.1.28 dev enp3s0 lladdr 8c:16:45:a2:3c:07 STALE
  • Each line is an address of the local network and its MAC address (lladdr). REACHABLE: used just now; STALE: an older answer; FAILED: nobody answered. Ignore the IPv6 lines, with fe80:: addresses.

For an address in another network, the frame goes to the MAC address of the gateway (see The Routing Table); the details are in The Way of a Packet.

Routing​

A router is a computer with a card in each network that it joins (see What Is a Network).

The Routing Table: ip route​

For every packet, the kernel looks in the routing table: one line for each network it can reach.

[student@fedora ~]$ ip route
default via 10.41.1.1 dev enp3s0 proto dhcp src 10.41.1.27 metric 100
10.41.1.0/24 dev enp3s0 proto kernel scope link src 10.41.1.27 metric 100
[student@fedora ~]$ ip route get 8.8.8.8
8.8.8.8 via 10.41.1.1 dev enp3s0 src 10.41.1.27 uid 1000
    cache
[student@fedora ~]$ ip route get 10.41.1.28
10.41.1.28 dev enp3s0 src 10.41.1.27 uid 1000
    cache
  • 10.41.1.0/24 dev enp3s0: the own network, reached directly.
  • default via 10.41.1.1: every other address goes to the default gateway, the router 10.41.1.1.
  • ip route get printed the line chosen for one address: 8.8.8.8 goes via the gateway, 10.41.1.28 directly.

When several lines match, the kernel picks the most specific one, with the longest mask: for 10.41.1.28, /24 beats default (/0). Think of the signs at a junction: "Bucharest center" beats "all directions".

The Routers on the Way: traceroute​

[student@fedora ~]$ traceroute -n 8.8.8.8
traceroute to 8.8.8.8 (8.8.8.8), 30 hops max, 60 byte packets

 2  141.85.241.1  1.203 ms  1.187 ms  1.164 ms
 3  * * *
 4  37.128.225.9  3.880 ms  3.871 ms  3.902 ms
 5  142.250.212.98  4.415 ms  4.402 ms  4.396 ms

  • One line for each router, in order: line 1 is the default gateway, the last line the destination. -n printed addresses, not names; * * * is a router that did not answer, but still forwarded the packets.

Every IP packet has a TTL (Time To Live), which each router decreases by 1; a router that gets it to 0 drops the packet and tells the sender (ICMP time exceeded). traceroute sends packets with TTL 1, 2, 3, ...: each one dies one router further, and that router tells who it is. tracepath -n does almost the same, and is always installed. Some firewalls drop the packets of traceroute: then every line after the last router that let them through is * * *.

Names: DNS​

DNS (Domain Name System) turns names, such as upb.ro, into IP addresses: the computer asks a DNS server, which knows the answer or asks other DNS servers. Think of the contacts of your phone: you choose a name, the phone dials the number.

[student@fedora ~]$ host upb.ro
upb.ro has address 141.85.220.33
upb.ro mail is handled by 0 ironport.upb.ro.
[student@fedora ~]$ resolvectl dns
Global:
Link 2 (enp3s0): 10.41.1.1
  • A name has several records: here its IPv4 address (A) and its mail server (MX).
  • enp3s0 asks the DNS server 10.41.1.1. resolvectl talks to systemd-resolved, the service that asks DNS for all the programs (the next lab sets it up).

Without DNS, ping 8.8.8.8 still works, but ping google.com says Temporary failure in name resolution: when "the Internet does not work", test an address and a name.

Automatic Configuration: DHCP​

The address, the mask, the gateway and the DNS server are written by hand (a static configuration, for servers), or given by a DHCP server. The address is leased for a time, and the client renews it before it expires. At home, the DHCP server is the home router. The client has no address yet, so it starts with a broadcast, over UDP (port 68 to port 67):

MessageFrom, toWhat it says
DISCOVERthe client, to everybodyis there a DHCP server?
OFFERthe server, to the clientI can give you 10.41.1.27/24, the gateway, the DNS, for 24 hours
REQUESTthe client, to everybodyI take 10.41.1.27, from the server 10.41.1.1
ACKthe server, to the clientit is yours

Containers​

A container is a lightweight virtual machine that shares the kernel of your computer. It has its own files, its own processes and its own network: cards, addresses, routing table and ports. It runs no kernel of its own, so it starts in a second and needs little memory. Think of a flat in a block of flats: its own door and address, but the same building (the kernel). Podman builds images and runs containers.

In this lab, a container is only a tool: a small computer, inside yours, to test the network on. For the exercises, Working in a Container is all you need; Running Containers explains how a container is made.

Ports: TCP and UDP​

A port, a number from 1 to 65535, finds the program inside a computer. A server waits on a fixed port: 22 for SSH, 53 for DNS, 80 and 443 for the Web; a client gets a random free port for each connection. Two protocols carry the data:

TCP (like a phone call)UDP (like a postcard)
a connectionyes: opened first, closed at the endno: each datagram travels alone
lost datanoticed, and sent againlost: the program handles it, if it cares
used bythe Web, SSH, e-mailDNS, DHCP, video calls, games

The Way of a Packet​

note

Going deeper

You do not need this section for the exercises of the lab, the 🧪 First Steps. Read it at home: the 🏠 Going Further exercises and the 📝 Challenges use it.

To send a packet, the kernel finds the next hop in the routing table (the destination, if it is in the network of the card, or else the gateway), finds its MAC address with ARP, and sends the packet in a frame to that MAC address. Each router takes the packet out of the frame, decreases its TTL, and sends it in a new frame to its own next hop. So the MAC addresses change at every router, and the IP addresses stay the same, except through NAT, which changes the source address. Think of a parcel that crosses the country: the address on it stays the same, but every van has another driver and another next stop.

[student@fedora ~]$ sudo tcpdump -i podman0 -n -t -e -c 1 icmp
6e:2b:91:5a:0c:7d > ce:5e:9a:1b:22:07, ethertype IPv4 (0x0800), length 98: 10.88.0.11 > 8.8.8.8: ICMP echo request, id 3, seq 1, length 64
[student@fedora ~]$ sudo tcpdump -i enp3s0 -n -t -e -c 1 icmp
8c:16:45:a2:3b:91 > 70:b5:e8:2d:91:4c, ethertype IPv4 (0x0800), length 98: 10.41.1.27 > 8.8.8.8: ICMP echo request, id 3, seq 1, length 64
  • Both captures ran while pc1 pinged 8.8.8.8. On podman0, the frame went from pc1 to podman0, with the source IP 10.88.0.11; on enp3s0, a new frame went from your card to the lab gateway (see ip neigh), with the source IP 10.41.1.27: your computer did NAT.

The way of a packet

  1. The next hop: bob says that a ping to 8.8.8.8 goes to the MAC address of 8.8.8.8. Prove him wrong, and follow one ping of pc1 across your computer. → The Way of a Packet

    1. capture one ICMP frame of your card, with its MAC addresses, while you ping 8.8.8.8, then your colleague; 2. capture one ICMP frame on podman0 and one on your card, in two terminals, while pc1 pings 8.8.8.8 from a third terminal;
    2. find whose each MAC address is.
    Hint

    man tcpdump: search for -e; /sys/class/net/<IF>/address; ip neigh.

    Check
    1. To 8.8.8.8, the destination MAC is the gateway's; to your colleague, it is your colleague's.
    2. On podman0: pc1 > podman0, 10.88.0.11 > 8.8.8.8; on your card: your card > the gateway, 10.41.1.27 > 8.8.8.8.

    Why: each hop puts the packet in a new frame, to the MAC address of its next hop.

  2. ARP on the wire: Watch pc1 ask for a MAC address, once with an answer and once without one. → Neighbors

    1. in a second terminal, capture the ARP frames of podman0, with their MAC addresses;
    2. from pc1, ping dhcp (10.88.0.10) once, then 10.88.0.99, which nobody has; print the neighbor table of pc1.
    Check
    1. Request who-has 10.88.0.10 tell 10.88.0.11 to ff:ff:ff:ff:ff:ff, and Reply 10.88.0.10 is-at ...; for 10.88.0.99, three requests and no reply, Destination Host Unreachable; the table has 10.88.0.10 ... REACHABLE and 10.88.0.99 dev eth0 FAILED.

  3. The routes of a container: For pc1, the lab is "another network". First guess how pc1 reaches each address, then check. → The Routing Table · The Routers on the Way

    3. from your computer, print the routers to upb.ro, and compare the first lines with exercise 6.
    Check
    1. 10.88.0.80 dev eth0: directly; 10.41.1.27 and 8.8.8.8 go via 10.88.0.1, because they are not in 10.88.0.0/16.
    2. One more line at the start: 1 10.88.0.1, then 2 10.41.1.1.
    3. The first lines are the same: every packet for another network leaves through the gateway.

  4. traceroute by hand: Find the first two routers with ping and a small TTL. → The Routers on the Way

Wrap-up Questions​
