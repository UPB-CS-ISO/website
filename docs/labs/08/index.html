08. Shell Scripting

In the seventh lab you built C programs in the terminal, and saw that a shell script is not compiled: bash reads it and runs it, line by line. In this lab you will write your own shell scripts. You will run them with the shebang #!/bin/bash or with bash, in a new process, or with source, in your own shell, and find their bugs with ShellCheck, in the terminal and, through a language server, in your editor. You will keep text in variables, and see how the shell cuts them into words at the characters of IFS. You will read input with read, capture the output of a command with command substitution, and compute with arithmetic expansion and bc. Then you will make decisions with if, test and case, repeat commands with the loops while and for, group commands into functions, give a script parameters, and make it stop at the first error with set -e.

The most important idea of this lab is that a script is a list of command lines, and the shell treats each one as it treats the line you type: it replaces the variables, cuts the result into words, and runs a command. Even the condition of if and while is a command, and only its exit code decides: 0 is true, anything else is false.

Objectives​

  • Write a script with a shebang and comments, run it with ./script.sh and with bash script.sh, and run it in your own shell with source script.sh
  • Follow a script, command by command, with bash -x
  • Find the usual bugs of a script before it runs with shellcheck, and see them in the editor through the language server bash-language-server
  • Keep text in variables, and understand why an unquoted $NAME is cut into words at the characters of IFS
  • Read a line typed by the user, or a line of a file, with read (-p, -r, several variables, IFS=: read)
  • Put the output of a command in a variable with command substitution, $(...)
  • Compute with integers with $((...)) and ((...)), and with decimals with bc
  • Make decisions with if, elif and else, from the exit code of a command, test, [ ], [[ ]] or (( ))
  • Compare a text with patterns with case
  • Repeat commands with while, until and while read, and leave a loop with break
  • Go over a list of words, the files of a glob or of find, or a range of numbers, with for, while read, seq and {1..5}
  • Write functions with local variables, give back a result with echo and success or failure with return
  • Read the parameters of a script, $0, $1, $# and "$@", and end it with exit
  • Stop a script at the first error with set -e, set -u and set -o pipefail, and clean up with trap

Shell Scripts​

A shell script is a text file with command lines. Instead of typing the commands one by one, you write them in the file, and bash runs them for you, one after another. Scripts are good at gluing commands together (copy, check, rename, report); for heavy computation, use a language like Python or C.

Writing a Script​

The examples of this lab run in ~/lab08, which exercise 1 creates. backup.sh copies fruits.txt into a folder:

~/lab08/backup.sh
#!/bin/bash
# copy the fruits into a backup folder
mkdir -p backup
cp fruits.txt \
   backup/
echo "backup done"; ls backup
Written asWhat it means
#!/bin/bashthe shebang, always the first line: the program that runs the script
# ...a comment: bash ignores the rest of the line
the end of a linethe end of a command: bash runs it, waits for it to end, then reads the next line
command1; command2two commands on one line: command1, then command2
\ at the end of a linethe command goes on, on the next line: cp gets both fruits.txt and backup/

Write the scripts with an editor from Text Editors in lab 06. The .sh at the end of the name is only a convention: Linux looks at the content of a file, not at its name.

Running a Script​

[student@fedora lab08]$ ./backup.sh
bash: ./backup.sh: Permission denied
[student@fedora lab08]$ bash backup.sh
backup done
fruits.txt
[student@fedora lab08]$ chmod +x backup.sh
[student@fedora lab08]$ ./backup.sh
backup done
fruits.txt
[student@fedora lab08]$ source backup.sh
backup done
fruits.txt
  • ./backup.sh failed: a new file does not have the x permission (see chmod in lab 05).
  • bash backup.sh worked anyway: the program is bash, and the script is only a file that it reads.
  • After chmod +x, the kernel read the shebang of ./backup.sh and ran /bin/bash ./backup.sh.
  • source backup.sh started no new process: your shell read the file and ran its lines itself.

CommandWho runs the linesWhat it needs
./backup.sha new bashthe x permission and the shebang; ./, because the current folder is not in PATH (lab 04)
bash backup.sha new bashonly the r permission; for bash, the shebang is a comment
source backup.shyour shellonly the r permission; the shebang is a comment

The shebang works for any language: a file that starts with #!/usr/bin/python3 is run by Python.

With ./ and bash, the script runs in a new bash process, a child of your shell. A cd or a variable of the script changes only that process, and the process ends with the script: your shell stays where it was. With source, what the script changes stays in your shell: see the next section. The exercises at home and the challenges need the details: they are in Subshells.

caution

Run your scripts with ./script.sh or with bash script.sh, not with sh script.sh: sh skips the shebang, and on Ubuntu it is dash, which does not know many features of bash (see Fedora and Ubuntu).

Running a Script in Your Shell: source​

source <FILE>, or its short name . <FILE>, starts no new process: it is a built-in command, and your shell reads the file and runs its lines, as if you typed them. What the file changes stays in your shell. Think of the way to a shop: with bash, you send a friend, and you stay home; with source, you walk there yourself.

~/lab08/go.sh
#!/bin/bash
cd photos
where="photos"
[student@fedora lab08]$ bash go.sh
[student@fedora lab08]$ echo "$PWD [$where]"
/home/student/lab08 []
[student@fedora lab08]$ source go.sh
[student@fedora photos]$ echo "$PWD [$where]"
/home/student/lab08/photos [photos]
[student@fedora photos]$ cd ..
  • bash go.sh went into photos and set where in a new bash, which then ended: your shell did not change.
  • source go.sh ran the same lines in your shell: the prompt shows photos, and where is still set.
CommandWho runs the linesWhat it needsWhat the file changes
./go.sha new bashthe x permission and the shebangis lost when it ends
bash go.sha new bashthe r permissionis lost when it ends
source go.sh, . go.shyour shellthe r permissionstays in your shell

Use source only for a file that must change your shell: ~/.bashrc, which bash reads in the same way when it starts (after you edit it, source ~/.bashrc applies it without a new terminal), or a file of functions that several scripts share. Run every other script with ./ or bash, so that it cannot change your shell by mistake.

caution

exit in a file run with source ends your shell, and the terminal closes. A file meant for source does not call exit.

Following a Script: bash -x​

bash -x prints every command, with a + in front, after the shell replaced the variables and before the command runs. It is the first thing to try when a script does something you did not expect:

[student@fedora lab08]$ bash -x backup.sh
+ mkdir -p backup
+ cp fruits.txt backup/
+ echo 'backup done'
backup done
+ ls backup
fruits.txt
tip

set -x on a line of the script turns the tracing on from there, and set +x turns it off: trace only the part you suspect.

Checking Scripts​

bash -x shows what a script does while it runs. ShellCheck finds the usual bugs before it runs, by reading the text of the script, like the warnings of gcc -Wall in lab 07. Install it, and the language server that shows its warnings in the editor, as Fedora and Ubuntu says.

Finding Bugs: shellcheck​

~/lab08/notes.sh
#!/bin/bash
# count the lines of a file
file="my notes.txt"
wc -l $file
[student@fedora lab08]$ bash notes.sh
wc: my: No such file or directory
wc: notes.txt: No such file or directory
0 total
[student@fedora lab08]$ shellcheck notes.sh

In notes.sh line 4:
wc -l $file
      ^---^ SC2086 (info): Double quote to prevent globbing and word splitting.

Did you mean:
wc -l "$file"
...
  • wc got two words, my and notes.txt: the unquoted $file was cut at the space (see Quoting and Escaping in lab 04).
  • shellcheck found the bug without running the script: the line, a ^---^ under the word, a code, SC2086, and the fix. https://www.shellcheck.net/wiki/SC2086 explains every code, with examples.

The warnings that you will meet in this lab:

CodeWhat it means
SC2086a variable without quotes: it is cut into words, and its globs are expanded
SC2162read without -r: it removes the \ characters

Variables​

You met the variables in Shell Variables and export in lab 04: NAME=value with no spaces around =, $NAME or ${NAME} to use it, unset to delete it. In a script, two rules matter most:

  • A variable holds text. msg="I like $fruit" keeps the value that fruit had then, not a formula, and $a+$b is just the text 2+3 (to compute, see Arithmetic).
  • A line starts with a command: in fruit= kiwi, the space ends the assignment, and kiwi is the command.
[student@fedora lab08]$ fruit=kiwi
[student@fedora lab08]$ echo "I like $fruit, ${fruit}s are green"
I like kiwi, kiwis are green
[student@fedora lab08]$ msg="I like $fruit"
[student@fedora lab08]$ fruit=plum
[student@fedora lab08]$ echo "$msg"
I like kiwi
[student@fedora lab08]$ a=2; b=3; echo $a+$b
2+3
[student@fedora lab08]$ fruit= kiwi
bash: kiwi: command not found
  • ${fruit}s needed the braces: $fruits is another variable, which does not exist.
  • msg did not change with fruit: the shell replaced $fruit when it ran the line msg=....
  • fruit= kiwi ran the command kiwi, with an empty fruit only for it (see A Variable for One Command in lab 04).

Splitting Words: IFS​

After it replaces an unquoted $NAME, the shell cuts the value into words at the characters of the variable IFS (Internal Field Separator). By default, IFS holds a space, a tab and a newline. Inside double quotes, "$NAME" stays one word (see Quoting and Escaping in lab 04). Think of the characters of IFS as the places where the scissors cut.

[student@fedora lab08]$ printf '%q\n' "$IFS"
$' \t\n'
[student@fedora lab08]$ x="Bob   Jones:20"
[student@fedora lab08]$ printf '[%s]\n' $x
[Bob]
[Jones:20]
[student@fedora lab08]$ printf '[%s]\n' "$x"
[Bob   Jones:20]
[student@fedora lab08]$ IFS=:
[student@fedora lab08]$ printf '[%s]\n' $x
[Bob   Jones]
[20]
[student@fedora lab08]$ unset IFS
  • printf '%q\n' showed the invisible characters of IFS: a space, \t (tab) and \n (newline).
  • printf '[%s]\n' prints every word it gets between brackets (lab 04): unquoted, $x became two words; quoted, one.
  • After IFS=:, only : cut the value, and the spaces were normal characters. unset IFS went back to the default.

The character of IFSHow it cuts
space, tab, newlineseveral in a row make one cut; at the start and at the end of the value, they are dropped
any other (:, ,)every one cuts: a::c gives three words, a, an empty word and c
caution

Put every variable in double quotes, "$NAME", unless you want it cut. After you change IFS, run unset IFS: until then, every unquoted variable is cut at the new characters.

Reading Input: read​

read is a built-in command of the shell (its manual is help read). It waits for a line, until Enter, and puts it in variables:

CommandWhat it does
read NAMEreads a single line from the standard input and assign it to NAME
read -p "<TEXT>" NAMEwrites the string <TEXT> (a prompt) first
read A B Ccuts the line at IFS: one word for every variable, and the last one takes the rest
IFS=: read A B Ccuts the line at :, only for this read
read -r NAMEraw: keeps the \ characters; without -r, read removes them
IFS= read -r NAMEreads the line exactly, with the spaces at its start and at its end
read NAME < <FILE>reads the first line of <FILE>
[student@fedora lab08]$ read -p "Full name: " first last
Full name: Carol Ann Smith
[student@fedora lab08]$ echo "$last, $first"
Ann Smith, Carol
[student@fedora lab08]$ head -n 1 /etc/passwd
root:x:0:0:Super User:/root:/bin/bash
[student@fedora lab08]$ IFS=: read user x uid rest < /etc/passwd
[student@fedora lab08]$ echo "$user has the UID $uid"
root has the UID 0
  • first got Carol, and last, the last variable, got the rest of the line.
  • IFS=: before read is a variable only for that command: the line was cut at :, and IFS stayed the default.
caution

IFS=: before another command does not cut its parameters

[student@fedora lab08]$ x="Bob   Jones:20"
[student@fedora lab08]$ IFS=: printf '[%s]\n' $x
[Bob]
[Jones:20]

The shell cuts $x into words before it starts printf, with its own IFS, the default. IFS=: reaches only the program that starts after that, and printf does not cut anything. read is different: it cuts the line that it reads, while it runs, so it sees IFS=:. To cut a variable at :, change IFS in the shell, on its own: IFS=:; printf '[%s]\n' $x; unset IFS prints [Bob Jones] and [20].

note

read ends with 0 when it read a line, and with 1 at the end of the input (Ctrl+D on the keyboard, or the end of a file): while read stops on it.

Command Substitution: $(...)​

$(command) runs the command and puts its output in its place, as text; then the shell runs the line. Use it to keep the output of a command in a variable, or to put it in the middle of a text. The newlines at the end of the output are dropped.

[student@fedora lab08]$ count=$(wc -l < fruits.txt)
[student@fedora lab08]$ echo "$count fruits on $(date +%A)"
7 fruits on Monday
[student@fedora lab08]$ echo "$(sort -u fruits.txt | wc -l) kinds"
5 kinds
  • count holds the text 7, the output of wc -l < fruits.txt; wc does not run again when you use $count.
  • $(...) works inside "...", and can hold a whole pipeline.

The command runs in a copy of the shell: a variable that it changes is changed only in the copy (see Subshells). `command` is the old way to write $(command).

Arithmetic​

For the shell, 2 and 3 are text: echo $a+$b prints 2+3. To compute, you must ask for it.

Integers: $((...)) and ((...))​

Written asWhat it does
$((<EXPR>))the shell computes <EXPR> and puts the result in its place, as text
((<EXPR>))a command that computes <EXPR>: to change a variable, ((n++)), or as a condition
expr <A> + <B>an old program that prints the result; each number and operator is a parameter, * is \*

Inside ((...)), the variables need no $, and the operators are those of C:

OperatorWhat it doesExample

% **remainder, power$((7 % 2)) is 1, $((2 ** 10)) is 1024

info

Some of these operators, such as **, ++ and --, are not available in every shell, and specifically not in sh. Always check which shell you're using with the echo $SHELL command.

[student@fedora lab08]$ a=7; b=2
[student@fedora lab08]$ echo "$a + $b = $((a + b))"
7 + 2 = 9
[student@fedora lab08]$ echo $((a / b)) $((a % b)) $((a ** b))
3 1 49
[student@fedora lab08]$ ((a++)); echo $a
8
[student@fedora lab08]$ echo $(a+b)
bash: a+b: command not found

  • $((a / b)) dropped the decimals: 7 / 2 is 3, with the remainder 1.
  • $(a+b), with one pair of parentheses, is command substitution: the shell looked for a command named a+b.

Decimals: bc​

bash computes only with integers. For decimals, write the expression as text and send it to bc, a calculator that reads expressions from its input and prints the results:

[student@fedora lab08]$ echo $((3.5 * 2))
bash: 3.5 * 2: syntax error: invalid arithmetic operator (error token is ".5 * 2")
[student@fedora lab08]$ echo "3.5 * 2" | bc
7.0
[student@fedora lab08]$ echo "10 / 3" | bc
3
[student@fedora lab08]$ echo "scale=2; 10 / 3" | bc
3.33
  • bc divides with no decimals, unless scale says how many to keep.
  • To keep the result, combine it with command substitution: total=$(echo "$price * $count" | bc).

Conditions​

if​

if runs a command and looks at its exit code (see Exit Codes in lab 06): when it is 0, the commands after then run; otherwise, if tries the next elif, or runs the commands after else. fi (if backwards) ends it; elif and else are optional.

~/lab08/kiwi.sh
#!/bin/bash
if grep -q kiwi fruits.txt; then
    echo "we have kiwi"
elif grep -q plum fruits.txt; then
    echo "no kiwi, but we have plums"
else
    echo "no kiwi, no plums"
fi

grep -q prints nothing: it only ends with 0 when it finds the text. The ; ends the command before then.

caution

The condition is a command line, not a formula. if $a > $b runs the command 7 (with a=7), and sends its output to a new file named 3: 7: command not found, so if takes the else branch. To compare, use test.

test and [​

test is a command that checks a condition, prints nothing, and ends with 0 (true) or 1 (false). [ is the same command, with one more rule: its last parameter must be ].

TestTrue when
<A> -eq <B>, -ne, -lt, -le, -gt, -gethe numbers are equal, not equal, <, <=, >, >=
"<S>" = "<T>", "<S>" != "<T>"the texts are equal, different
-z "<S>", -n "<S>"the text is empty, not empty
-e <FILE>, -f <FILE>, -d <FILE>it exists; it is a regular file; it is a directory
-r <FILE>, -w <FILE>, -x <FILE>you may read, write, run it
! <TEST>the test is false
[student@fedora lab08]$ a=2; b=3
[student@fedora lab08]$ [ $a -lt $b ]; echo $?
0
[student@fedora lab08]$ [ -d fruits.txt ]; echo $?
1
[student@fedora lab08]$ type -a [
[ is a shell builtin
[ is /usr/bin/[
[student@fedora lab08]$ [$a -lt $b]
bash: [2: command not found
  • type -a showed that [ is a built-in command, and also a program in /usr/bin.
  • [$a -lt $b] became the word [2, and there is no command with that name.
caution

[ is a command: the shell cuts the line into words before [ starts. Put spaces around [, ] and every operator, and quote the variables: with an empty x, [ $x = abc ] becomes [ = abc ], and [ says =: unary operator expected; [ "$x" = abc ] works. Compare numbers with -lt, not <: inside [ ], < and > are redirects.

[[ ]] and (( ))​

bash has two easier forms. They are part of the language of bash (keywords), not commands, so they work only in bash, not in sh:

FormWhat it adds
[[ <TEST> ]]like [, but an unquoted variable is not cut, && and || work inside, and == takes a glob
(( <EXPR> ))the arithmetic of $((...)) as a condition: true when the result is not 0
[student@fedora lab08]$ if (( a < b )); then echo "smaller"; fi
smaller
[student@fedora lab08]$ f="my notes.txt"; [[ $f == *.txt ]] && echo "a text file"
a text file

Choosing by Pattern: case​

case compares a text with patterns, from top to bottom, and runs the branch of the first one that matches. The patterns are globs (see Globbing in lab 04), and | between them means or:

~/lab08/color.sh
#!/bin/bash
read -p "Fruit: " fruit
case $fruit in
    banana | lemon)
        echo "yellow" ;;
    kiwi | lime)
        echo "green" ;;
    *berry)
        echo "a berry" ;;
    *)
        echo "I do not know $fruit" ;;
esac
  • ;; ends a branch: case jumps after esac (case backwards), and does not try the other patterns.
  • *) matches anything: the default branch, always the last one. Without it, when nothing matches, nothing runs.

Loops​

while and until​

while runs a command before every round: while it ends with 0, while runs the body, the commands between do and done. until is the opposite: it repeats while the command does not end with 0.

~/lab08/countdown.sh
#!/bin/bash
n=3
while [ $n -gt 0 ]; do
    echo "$n..."
    n=$((n - 1))
done
echo "go!"
[student@fedora lab08]$ bash countdown.sh

A function is a group of commands with a name. You call it like any command, and the words after its name are its parameters: $1, $2, ... and $#, how many. Define a function before the line that calls it.

Handling Errors​

When a command fails, bash prints its error and goes on with the next line, as in the terminal. A script that goes on after an error can do the right thing in the wrong place:

~/lab08/tidy.sh
#!/bin/bash
# clean up the photos
cd photoz
rm -f *.tmp
echo "photos cleaned"
[student@fedora lab08]$ bash tidy.sh
tidy.sh: line 3: cd: photoz: No such file or directory
photos cleaned
[student@fedora lab08]$ echo $?
0
  • cd failed (the folder is photos), but rm ran anyway, in ~/lab08: it deleted the .tmp files of the wrong folder.
  • The script ended with 0, the exit code of echo, its last command: whoever ran it thinks that it worked.

You can check a command yourself: cd photoz || exit 1 ends the script when cd fails (see Chaining Commands in lab 06). To check every command, use set.

Stopping at the First Error: set -e​

set changes the options of the shell that runs it. set -e (errexit), on its own line near the top of the script, stops the script at the first command that fails, with the exit code of that command:

~/lab08/tidy.sh
#!/bin/bash
# clean up the photos
set -e
cd photoz
rm -f *.tmp
echo "photos cleaned"
[student@fedora lab08]$ bash tidy.sh
tidy.sh: line 4: cd: photoz: No such file or directory
[student@fedora lab08]$ echo $?
1

A command whose exit code is checked does not stop the script: that is how you allow a failure.

Line, with set -eWhen the first command fails
cd photozthe script stops
cd photoz || exit 2exit 2 runs: you choose the exit code, or what to do instead

caution

With set -e, a ((...)) whose result is 0 stops the script: n=0; ((n++)) computes the old value of n, 0, so it ends with 1. Count with n=$((n + 1)).

Cleaning Up: trap​

trap '<COMMANDS>' EXIT runs the commands when the script ends, however it ends: after the last line, at exit, or stopped by set -e. Use it to delete the temporary files, made with mktemp (a new empty file with a unique name in /tmp). trap '<COMMANDS>' ERR runs the commands after every command that fails, where set -e would stop: with $LINENO, it says where the script stopped.

~/lab08/mango.sh
#!/bin/bash
set -e
tmp=$(mktemp)
trap 'rm -f "$tmp"; echo "removed $tmp"' EXIT
trap 'echo "failed at line $LINENO" >&2' ERR
sort fruits.txt > "$tmp"
grep -q mango "$tmp"
echo "found a mango"
[student@fedora lab08]$ bash mango.sh
failed at line 7
removed /tmp/tmp.7gIFP38nMM
[student@fedora lab08]$ echo $?
1
  • grep -q printed nothing, and ended with 1: set -e stopped the script, which, without the ERR trap, would have stopped in silence.
  • The EXIT trap deleted the temporary file, even if the script did not reach its last line.
  • The single quotes keep $tmp and $LINENO as they are, until the trap runs.

Extra​

  1. shfmt: a program that formats a script, with the same indentation everywhere, as clang-format does for C. Install it (sudo dnf install shfmt; Ubuntu: sudo apt install shfmt), then shfmt -d what.sh shows what it would change; bash-language-server uses it to format the file from the editor. → github.com/mvdan/sh
  2. Parameter expansion: bash can change the value of a variable without other programs: ${f%.jpeg} drops the end .jpeg, ${f##*/} keeps what follows the last /, ${name:-guest} gives guest when name is empty. → man bash, search for Parameter Expansion
  3. Arrays: fruits=(apple kiwi "star fruit") keeps several values in one variable; "${fruits[@]}" gives them back, one word each, like "$@". → man bash, search for Arrays
