08. Scripturi de shell

În laboratorul 7 ați compilat programe C în terminal și ați văzut că un script de shell nu se compilează: bash îl citește și îl rulează, linie cu linie. În acest laborator scrieți propriile scripturi de shell. Le rulați cu shebang-ul #!/bin/bash sau cu bash, într-un proces nou, ori cu source, în propriul shell, și le găsiți bug-urile cu ShellCheck, în terminal și, printr-un server de limbaj (language server), direct în editor. Păstrați text în variabile și vedeți cum îl taie shell-ul în cuvinte la caracterele din IFS. Citiți date de intrare cu read, preluați rezultatul unei comenzi cu substituția de comenzi și faceți calcule cu expandarea aritmetică și cu bc. Apoi luați decizii cu if, test și case, repetați comenzi cu buclele while și for, grupați comenzi în funcții, dați unui script parametri și îl faceți să se oprească la prima eroare cu set -e.

Cea mai importantă idee a laboratorului: un script este o listă de linii de comandă, iar shell-ul o tratează pe fiecare exact ca pe linia pe care o tastați voi: înlocuiește variabilele, taie rezultatul în cuvinte și rulează o comandă. Chiar și condiția din if și din while este o comandă, iar decizia o ia doar codul ei de ieșire: 0 înseamnă adevărat, orice altceva înseamnă fals.

Obiective​

  • Să scrieți un script cu shebang și comentarii, să îl rulați cu ./script.sh și cu bash script.sh și să îl rulați în propriul shell cu source script.sh
  • Să urmăriți un script, comandă cu comandă, cu bash -x
  • Să găsiți bug-urile obișnuite ale unui script înainte să ruleze, cu shellcheck, și să le vedeți în editor prin serverul de limbaj bash-language-server
  • Să păstrați text în variabile și să înțelegeți de ce un $NAME fără ghilimele este tăiat în cuvinte la caracterele din IFS
  • Să citiți o linie tastată de utilizator sau o linie dintr-un fișier cu read (-p, -r, mai multe variabile, IFS=: read)
  • Să puneți rezultatul unei comenzi într-o variabilă cu substituția de comenzi, $(...)
  • Să faceți calcule cu numere întregi cu $((...)) și ((...)), iar cu numere zecimale cu bc
  • Să luați decizii cu if, elif și else, pe baza codului de ieșire al unei comenzi, test, [ ], [[ ]] sau (( ))
  • Să comparați un text cu tipare (patterns) folosind case
  • Să repetați comenzi cu while, until și while read și să ieșiți dintr-o buclă cu break
  • Să parcurgeți o listă de cuvinte, fișierele dintr-un glob sau găsite de find ori un șir de numere, cu for, while read, seq și {1..5}
  • Să scrieți funcții cu variabile local, care întorc un rezultat cu echo, iar succesul sau eșecul cu return
  • Să citiți parametrii unui script, $0, $1, $# și "$@", și să îl încheiați cu exit
  • Să opriți un script la prima eroare cu set -e, set -u și set -o pipefail și să faceți curat cu trap

Scripturi de shell​

Un script de shell este un fișier text cu linii de comandă. În loc să tastați comenzile una câte una, le scrieți în fișier, iar bash le rulează în locul vostru, una după alta. Scripturile sunt foarte bune la lipit comenzi între ele (copiază, verifică, redenumește, raportează); pentru calcule complicate, folosiți un limbaj ca Python sau C.

Scrierea unui script​

Exemplele din acest laborator rulează în ~/lab08, director creat de exercițiul 1. backup.sh copiază fruits.txt într-un director:

~/lab08/backup.sh
#!/bin/bash
# copy the fruits into a backup folder
mkdir -p backup
cp fruits.txt \
   backup/
echo "backup done"; ls backup
Scris caCe înseamnă
#!/bin/bashshebang-ul, mereu pe prima linie: programul care rulează scriptul
# ...un comentariu: bash ignoră restul liniei
sfârșitul unei liniisfârșitul unei comenzi: bash o rulează, așteaptă să se termine, apoi citește linia următoare
command1; command2două comenzi pe aceeași linie: întâi command1, apoi command2
\ la sfârșitul unei liniicomanda continuă pe linia următoare: cp primește atât fruits.txt, cât și backup/

Scrieți scripturile cu unul dintre editoarele din Editoare de text, din laboratorul 06. Terminația .sh din nume este doar o convenție: Linux se uită la conținutul unui fișier, nu la numele lui.

Rularea unui script​

Încercăm să rulăm scriptul în cele trei moduri:

[student@fedora lab08]$ ./backup.sh
bash: ./backup.sh: Permission denied
[student@fedora lab08]$ bash backup.sh
backup done
fruits.txt
[student@fedora lab08]$ chmod +x backup.sh
[student@fedora lab08]$ ./backup.sh
backup done
fruits.txt
[student@fedora lab08]$ source backup.sh
backup done
fruits.txt
  • ./backup.sh a eșuat: un fișier nou nu are permisiunea x (vedeți chmod în laboratorul 05).
  • bash backup.sh a mers totuși: programul este bash, iar scriptul e doar un fișier pe care acesta îl citește.
  • După chmod +x, nucleul a citit shebang-ul din ./backup.sh și a rulat /bin/bash ./backup.sh.
  • source backup.sh nu a pornit niciun proces nou: shell-ul vostru a citit fișierul și i-a rulat singur liniile.

ComandăCine rulează liniileDe ce are nevoie
./backup.shun bash noude permisiunea x și de shebang; de ./, pentru că directorul curent nu este în PATH (laboratorul 04)
bash backup.shun bash noudoar de permisiunea r; pentru bash, shebang-ul este un comentariu
source backup.shshell-ul vostrudoar de permisiunea r; shebang-ul este un comentariu

Shebang-ul funcționează pentru orice limbaj: un fișier care începe cu #!/usr/bin/python3 este rulat de Python.

Cu ./ și cu bash, scriptul rulează într-un proces bash nou, copil al shell-ului vostru. Un cd sau o variabilă din script schimbă doar acel proces, iar procesul se termină odată cu scriptul: shell-ul vostru rămâne unde era. Cu source, ce schimbă scriptul rămâne în shell-ul vostru: vedeți secțiunea următoare. Exercițiile de acasă și provocările au nevoie de detalii, pe care le găsiți în Subshell-uri.

atenție

Rulați scripturile cu ./script.sh sau cu bash script.sh, nu cu sh script.sh: sh ignoră shebang-ul, iar pe Ubuntu este dash, care nu cunoaște multe dintre funcționalitățile bash (vedeți Fedora și Ubuntu).

Rularea unui script în propriul shell: source​

source <FILE>, sau numele lui scurt, . <FILE>, nu pornește niciun proces nou: este o comandă internă, iar shell-ul vostru citește fișierul și îi rulează liniile, ca și cum le-ați fi tastat voi. Ce schimbă fișierul rămâne în shell-ul vostru. Gândiți-vă la drumul până la un magazin: cu bash, trimiteți un prieten și voi rămâneți acasă; cu source, mergeți chiar voi acolo.

~/lab08/go.sh
#!/bin/bash
cd photos
where="photos"
[student@fedora lab08]$ bash go.sh
[student@fedora lab08]$ echo "$PWD [$where]"
/home/student/lab08 []
[student@fedora lab08]$ source go.sh
[student@fedora photos]$ echo "$PWD [$where]"
/home/student/lab08/photos [photos]
[student@fedora photos]$ cd ..
  • bash go.sh a intrat în photos și a setat where într-un bash nou, care apoi s-a terminat: shell-ul vostru nu s-a schimbat.
  • source go.sh a rulat aceleași linii în shell-ul vostru: prompt-ul arată photos, iar where este încă setată.
ComandaCine rulează liniileDe ce are nevoieCe schimbă fișierul
./go.shun bash noude permisiunea x și de shebangse pierde când se termină
bash go.shun bash noude permisiunea rse pierde când se termină
source go.sh, . go.shshell-ul vostrude permisiunea rrămâne în shell-ul vostru

Folosiți source doar pentru un fișier care trebuie să vă schimbe shell-ul: ~/.bashrc, pe care bash îl citește în același fel când pornește (după ce îl modificați, source ~/.bashrc îl aplică fără un terminal nou), sau un fișier cu funcții folosite de mai multe scripturi. Rulați orice alt script cu ./ sau cu bash, ca să nu vă poată schimba shell-ul din greșeală.

atenție

exit într-un fișier rulat cu source încheie shell-ul vostru, iar terminalul se închide. Un fișier făcut pentru source nu apelează exit.

Urmărirea unui script: bash -x​

bash -x afișează fiecare comandă, precedată de un +, după ce shell-ul a înlocuit variabilele și înainte ca comanda să ruleze. Este primul lucru de încercat când un script face altceva decât vă așteptați:

[student@fedora lab08]$ bash -x backup.sh
+ mkdir -p backup
+ cp fruits.txt backup/
+ echo 'backup done'
backup done
+ ls backup
fruits.txt
sfat

O linie set -x în script pornește urmărirea de acolo înainte, iar set +x o oprește: urmăriți doar partea pe care o bănuiți.

Verificarea scripturilor​

bash -x arată ce face un script în timp ce rulează. ShellCheck găsește bug-urile obișnuite înainte ca scriptul să ruleze, citindu-i textul, la fel ca avertismentele din gcc -Wall din laboratorul 07. Instalați-l, împreună cu serverul de limbaj care îi afișează avertismentele în editor, ca în Fedora și Ubuntu.

Did you mean:

...
  • wc a primit două cuvinte, my și notes.txt: $file, fără ghilimele, a fost tăiat la spațiu (vedeți Ghilimele și caractere speciale în laboratorul 04).

Variabile​

Ați întâlnit variabilele în Variabile de shell și export, în laboratorul 04: NAME=value fără spații în jurul lui =, $NAME sau ${NAME} pentru a o folosi, unset pentru a o șterge. Într-un script, contează mai ales două reguli:

  • O variabilă conține text. msg="I like $fruit" păstrează valoarea pe care o avea fruit atunci, nu o formulă, iar $a+$b este doar textul 2+3 (pentru calcule, vedeți Aritmetică).
  • O linie începe cu o comandă: în fruit= kiwi, spațiul încheie atribuirea, iar kiwi este comanda.
[student@fedora lab08]$ fruit=kiwi
[student@fedora lab08]$ echo "I like $fruit, ${fruit}s are green"
I like kiwi, kiwis are green
[student@fedora lab08]$ msg="I like $fruit"
[student@fedora lab08]$ fruit=plum
[student@fedora lab08]$ echo "$msg"
I like kiwi
[student@fedora lab08]$ a=2; b=3; echo $a+$b
2+3
[student@fedora lab08]$ fruit= kiwi
bash: kiwi: command not found
  • ${fruit}s a avut nevoie de acolade: $fruits este o altă variabilă, care nu există.
  • msg nu s-a schimbat odată cu fruit: shell-ul a înlocuit $fruit în momentul în care a rulat linia msg=....
  • fruit= kiwi a rulat comanda kiwi, cu fruit gol doar pentru ea (vedeți O variabilă pentru o singură comandă în laboratorul 04).

Împărțirea în cuvinte: IFS​

După ce înlocuiește un $NAME fără ghilimele, shell-ul taie valoarea în cuvinte la caracterele din variabila IFS (Internal Field Separator). Implicit, IFS conține un spațiu, un tab și un caracter de linie nouă. Între ghilimele duble, "$NAME" rămâne un singur cuvânt (vedeți Ghilimele și caractere speciale în laboratorul 04). Gândiți-vă la caracterele din IFS ca la locurile în care taie foarfeca.

[student@fedora lab08]$ printf '%q\n' "$IFS"
$' \t\n'
[student@fedora lab08]$ x="Bob   Jones:20"
[student@fedora lab08]$ printf '[%s]\n' $x
[Bob]
[Jones:20]
[student@fedora lab08]$ printf '[%s]\n' "$x"
[Bob   Jones:20]
[student@fedora lab08]$ IFS=:
[student@fedora lab08]$ printf '[%s]\n' $x
[Bob   Jones]
[20]
[student@fedora lab08]$ unset IFS
  • printf '%q\n' a afișat caracterele invizibile din IFS: un spațiu, \t (tab) și \n (linie nouă).
  • printf '[%s]\n' afișează între paranteze drepte fiecare cuvânt primit (laboratorul 04): fără ghilimele, $x a devenit două cuvinte; cu ghilimele, unul.
  • După IFS=:, valoarea s-a tăiat doar la :, iar spațiile au fost caractere obișnuite. unset IFS a revenit la valoarea implicită.

Caracterul din IFSCum taie
spațiu, tab, linie nouămai multe la rând fac o singură tăietură; la începutul și la sfârșitul valorii sunt eliminate
oricare altul (:, ,)taie fiecare: a::c dă trei cuvinte, a, un cuvânt gol și c
atenție

Puneți fiecare variabilă între ghilimele duble, "$NAME", în afară de cazul în care vreți să fie tăiată. După ce schimbați IFS, rulați unset IFS: până atunci, orice variabilă fără ghilimele se taie la noile caractere.

Citirea datelor de intrare: read​

read este o comandă internă a shell-ului (manualul ei se afișează cu help read). Așteaptă o linie, până la Enter, și o pune în variabile:

ComandăCe face
read NAMEcitește o singură linie de la intrarea standard și o pune în NAME
read -p "<TEXT>" NAMEafișează mai întâi textul <TEXT> (un prompt)
read A B Ctaie linia la IFS: câte un cuvânt pentru fiecare variabilă, iar ultima primește restul
IFS=: read A B Ctaie linia la :, doar pentru acest read
read -r NAMEraw: păstrează caracterele \; fără -r, read le elimină
IFS= read -r NAMEcitește linia exact cum este, cu spațiile de la început și de la sfârșit
read NAME < <FILE>citește prima linie din <FILE>
[student@fedora lab08]$ read -p "Full name: " first last
Full name: Carol Ann Smith
[student@fedora lab08]$ echo "$last, $first"
Ann Smith, Carol
[student@fedora lab08]$ head -n 1 /etc/passwd
root:x:0:0:Super User:/root:/bin/bash
[student@fedora lab08]$ IFS=: read user x uid rest < /etc/passwd
[student@fedora lab08]$ echo "$user has the UID $uid"
root has the UID 0
  • first a primit Carol, iar last, ultima variabilă, a primit restul liniei.
  • IFS=: înaintea lui read este o variabilă doar pentru acea comandă: linia s-a tăiat la :, iar IFS a rămas la valoarea implicită.
atenție

IFS=: înaintea altei comenzi nu îi taie parametrii

[student@fedora lab08]$ x="Bob   Jones:20"
[student@fedora lab08]$ IFS=: printf '[%s]\n' $x
[Bob]
[Jones:20]

Shell-ul taie $x în cuvinte înainte să pornească printf, cu propriul IFS, cel implicit. IFS=: ajunge doar la programul care pornește după aceea, iar printf nu taie nimic. read este altfel: taie linia pe care o citește el, în timp ce rulează, așa că vede IFS=:. Ca să tăiați o variabilă la :, schimbați IFS în shell, separat: IFS=:; printf '[%s]\n' $x; unset IFS afișează [Bob Jones] și [20].

notă

Substituția de comenzi: $(...)​

$(command) rulează comanda și pune în locul ei rezultatul afișat, ca text; abia apoi shell-ul rulează linia. Folosiți-o ca să păstrați rezultatul unei comenzi într-o variabilă sau ca să îl puneți în mijlocul unui text. Caracterele de linie nouă de la sfârșitul rezultatului se elimină.

[student@fedora lab08]$ count=$(wc -l < fruits.txt)
[student@fedora lab08]$ echo "$count fruits on $(date +%A)"

[student@fedora lab08]$ echo "$(sort -u fruits.txt | wc -l) kinds"
5 kinds
  • count conține textul 7, rezultatul lui wc -l < fruits.txt; wc nu mai rulează din nou când folosiți $count.
  • $(...) funcționează și în interiorul "..." și poate conține un pipeline întreg.

Comanda rulează într-o copie a shell-ului: o variabilă pe care o schimbă se schimbă doar în copie (vedeți Subshell-uri). `command` este vechea formă de a scrie $(command).

Condiții​

if​

if rulează o comandă și se uită la codul ei de ieșire (vedeți Coduri de ieșire în laboratorul 06): dacă este 0, rulează comenzile de după then; altfel, if încearcă următorul elif sau rulează comenzile de după else. fi (if scris invers) încheie construcția; elif și else sunt opționale.

#!/bin/bash

    echo "we have kiwi"
elif grep -q plum fruits.txt; then
    echo "no kiwi, but we have plums"

atenție

Condiția este o linie de comandă, nu o formulă. if $a > $b rulează comanda 7 (cu a=7) și îi trimite rezultatul într-un fișier nou numit 3: apare 7: command not found, așa că if intră pe ramura else. Pentru comparații, folosiți test.

Funcții​

O funcție este un grup de comenzi cu un nume. O apelați ca pe orice comandă, iar cuvintele de după numele ei sunt parametrii ei: $1, $2, ... și $#, numărul lor. Definiți funcția înaintea liniei care o apelează.

        return 1
    fi
    echo "Hello, $1!"
}

add() {
    local sum=$(($1 + $2))
    echo "$sum"
}

greet || echo "nobody to greet"

Întrebări de recapitulare​

Folosiți ultimele 5 minute ale laboratorului ca să răspundeți la aceste întrebări împreună cu colegii și cu asistentul. La ultimele două nu există răspunsuri greșite.

  1. Care este diferența dintre ./script.sh, bash script.sh și source script.sh? Ce face shebang-ul?
  2. Ce găsește shellcheck și nu poate găsi bash -x, și invers?
  3. De ce nu se schimbă msg="I like $fruit" când se schimbă fruit? Care este diferența dintre $(...) și $((...))?
  4. Când taie shell-ul o variabilă în cuvinte și unde? Cum îl opriți?
  5. Ce verifică de fapt if? De ce trebuie să existe spații în interiorul [ ... ]?
  6. Cum parcurgeți liniile unui fișier și cum parcurgeți fișierele unui director? De ce nu for f in $(ls)?
  7. Cum întoarce o funcție un număr și cum anunță că a eșuat? Ce sunt $1, $# și "$@"?
  8. Ce schimbă set -e într-un script? De ce nu se oprește la o condiție eșuată a lui if?
  9. Ce eroare a shell-ului v-a surprins cel mai mult azi?
  10. Ce sarcină pe care o făceați până acum de mână o veți transforma într-un script?

Extra​

  1. shfmt: un program care formatează un script, cu aceeași indentare peste tot, așa cum face clang-format pentru C. Instalați-l (sudo dnf install shfmt; pe Ubuntu: sudo apt install shfmt), apoi shfmt -d what.sh arată ce ar schimba; bash-language-server îl folosește ca să formateze fișierul direct din editor. → github.com/mvdan/sh
  2. Expandarea parametrilor: bash poate schimba valoarea unei variabile fără alte programe: ${f%.jpeg} elimină terminația .jpeg, ${f##*/} păstrează ce urmează după ultimul /, iar ${name:-guest} dă guest când name este goală. → man bash, căutați Parameter Expansion
  3. Vectori (arrays): fruits=(apple kiwi "star fruit") păstrează mai multe valori într-o singură variabilă; "${fruits[@]}" le dă înapoi, fiecare ca un cuvânt separat, la fel ca "$@". → man bash, căutați Arrays
