    File system layout

    Drive letters vs. one root

    Why it matters

    Every command in this lecture takes a path. A path only makes sense once you know the shape of the tree it walks: on Linux there is exactly one tree, and every disk, USB stick and even the running processes hang somewhere below /.

    Windows

    • one tree per drive letter: C:\, D:\, E:\ ...
    • each partition is an independent file system
    • separator \ (backslash), names are case-insensitive: Readme.txt and README.TXT are the same file

    Linux (POSIX)

    • one single root /, no drive letters
    • other disks are mounted in a directory of the same tree (/media/alice/USB_STICK)
    • separator /, names are case-sensitive: Movies and movies are two different directories

    The Linux layout

    What every directory is for

    Each directory directly below / has a job. You do not need to memorize them, but you should recognize them when a path starts with one.

    All the directories in one table
    DirectoryWhat lives thereWindows equivalent
    /the top of the tree, the start of every absolute pathC:\
    /bin, /sbinessential programs: ls, cp, mv (everyone), mount, fsck, reboot (the administrator). On modern distributions they point to /usr/bin and /usr/sbinC:\Windows\System32
    /bootstarting the system: the kernel vmlinuz-6.x, the initial RAM disk initrd.img-6.x, grub/grub.cfgthe EFI partition, C:\Windows\Boot

    Common mistake

    /root is the root directory

    / is the root of the file system. /root is only the home directory of the user called root, one directory below /.

    Instead: say slash for / and slash root for /root.

    Where a file is

    Absolute and relative paths

    Why it matters

    Every file argument of every command is a path. Mixing up absolute and relative paths is the most common reason a command answers No such file or directory while the file is right there.

    A path tells the operating system where a file or a directory is. Every running program has exactly one current directory at a time, and a relative path starts from it.

    Absolute: from the root

    Starts with / on Linux, with a drive letter on Windows. It means the same thing from anywhere.

    $ ls /home/alice/Movies/the_odyssey.mkv
/home/alice/Movies/the_odyssey.mkv
    Windows: C:\Users\Alice\Videos\the_odyssey.mkv, D:\Trailers\avatar_fire_and_ash.mp4

    Like a full postal address: country → county → city → street → number → person.

    Relative: from where you are

    Does not start with /. Shorter, but its meaning changes with the current directory.

    $ pwd
/home/alice
$ ls Movies/the_odyssey.mkv
Movies/the_odyssey.mkv
    Windows: from C:\Users\Alice: Videos\the_odyssey.mkv

    Like directions from where you stand: you already know the country and the city.

    Why relative paths exist

    A program finds its own files with relative paths (./textures), wherever it is installed. A script that only uses absolute paths breaks as soon as it is copied to another directory or another user.

    Check yourself

    The current directory is /home/alice/Downloads. Which file does Movies/the_odyssey.mkv refer to?

    . .. / ~

    Special path symbols

    MeaningWindowsLinuxNotes
    current directory..the directory you are in
    parent directory....one level up
    separator\/between the names of a path
    rootdrive + \ (C:\)/the top of the tree
    home directory%USERPROFILE%~expanded by bash to /home/alice

    \ on Linux is not a separator

    It *escapes* the next character: my\ file.txt is one name with a space in it. ..\Videos is a Windows path.

    ~ belongs to the shell

    bash replaces ~ with your home directory before the command runs. In quotes ("~") it is a plain character.

    Windows also accepts /

    C:/Program Files/App works in most programs. The reverse is not true: Linux never accepts \ as a separator.

    Where am I, where is my parent

    . and ..

    Why it matters

    Most paths you type are relative and climb the tree with ... Reading them one part at a time, the way the kernel does, removes all the guessing.

    Every directory has two hidden entries:

    • 📍 . the directory itself
    • ⬆️ .. its parent
    • 🔁 .. can be chained, each one goes one level up: ../..
    • ⚠️ /.. is still /: the root has no parent

    From relative to absolute

    Walking a path, step by step

    Read the path from left to right. Each part is one move in the tree, starting from 📍 /home/alice/Movies. Under the path, the same walk on paper: glue the path to the current directory, then cancel the parts.

    Reading a manual page

    Why it matters

    The manual installed on your computer describes exactly the version you run. Web pages and AI answers are often for another version, or simply wrong; the manual is the reference you check them against.

    PartWhat it tells you
    PWD(1)the name and the section of the page; section 1 is User Commands
    NAMEwhat the command is, in one line
    SYNOPSIShow to call it: [ ] is optional, ... can repeat
    DESCRIPTIONwhat it does and every option: -P short, --physical long, same meaning
    EXIT STATUS0 means success, anything else is an error
    EXAMPLEScommands to try and what they print
    SEE ALSOrelated pages: cd(1) is the page of cd in section 1

    Inside the viewer

    man shows the page in less, a viewer driven by single keys. You do not know the option yet, so search for what you want to do: /reverse finds -r, --reverse. For a quick summary instead of the whole page, most commands print one with --help: ls --help.

    Commands take paths, not just names

    Files are paths

    When a command expects a file or a directory, it accepts any path to it. All four commands below, run from /home/alice/Movies, print the same file.

    $ cat ../watchlist.txt  # relative, glued to /home/alice/Movies
Project Hail Mary
$ cat /home/alice/watchlist.txt  # absolute, from /
Project Hail Mary
$ cat ~/watchlist.txt  # ~ is /home/alice
Project Hail Mary
$ cat ../../alice/Downloads/../watchlist.txt  # a detour
Project Hail Mary

    cat prints the content of a file.

    Paths in the SYNOPSIS

    In a manual, FILE, DIR, SOURCE and DEST almost always mean a path. Relative and absolute paths can be mixed in the same command.

    cd [DIR]
    ls [OPTION]... [FILE]...
    cp [OPTION]... SOURCE DEST
    mv [OPTION]... SOURCE DEST
    mkdir [OPTION]... DIRECTORY...
    rm [OPTION]... [FILE]...
    $ cp ../watchlist.txt /tmp/
$ mv /tmp/watchlist.txt ~/Downloads/
$ ls -l ~/Documents ../Downloads

    Relative paths depend on where you are

    cp ../watchlist.txt /tmp/ copies a different file (or fails) when you run it from another directory. Check with pwd, or look at the prompt, before you run a command with relative paths.

    Where am I, go there

    pwd and cd

    Why it matters

    The current directory decides what every relative path means. pwd tells you where you are, cd moves you; together they replace the address bar of a graphical file manager.

    pwd: print working directory

    Prints the absolute path of the current directory.

    $ pwd
/home/alice/Movies

    The prompt alice@iso:~/Movies$ already shows it, with ~ for the home directory.

    cd: change directory

    cd [DIR] # no DIR: go to the home directory
    $ cd /home/alice/Downloads  # absolute
$ cd ../Movies  # relative
$ cd -  # the previous directory
/home/alice/Downloads
$ cd -
/home/alice/Movies
$ cd ~  # home
$ cd  # home, too
    Common mistake

    cd - means back

    cd - switches between the last two directories, like the button that toggles between two TV channels. Pressed again, it returns where you were, not one step further back.

    Instead: cd .. to go up one level, cd - to toggle.

    List a directory

    ls

    ls [OPTION]... [FILE]...
    $ ls
Downloads  Movies  watchlist.txt
$ ls watchlist.txt Movies
watchlist.txt

Movies:
the_odyssey.mkv
$ ls -a
.  ..  .bashrc  Downloads  Movies  watchlist.txt

    • a file is listed by its name, a directory by what is inside it

    A directory and everything inside

    tree

    tree [OPTION]... [DIRECTORY]...
    $ tree
.
├── Downloads
│   └── supergirl.mp4
├── Movies
│   └── the_odyssey.mkv
└── watchlist.txt

3 directories, 3 files
    • ls lists one directory, tree also goes inside every directory
    • tree Movies Downloads only these directories
    • -L 1 only one level deep
    • -d only directories
    • -a include hidden files
    • the count includes the starting directory: . plus Downloads and Movies are 3

    Not installed by default

    Ubuntu: sudo apt install tree, Fedora: sudo dnf install tree.

    Search by name and type

    find

    find [DIRECTORY]... [FILTER]...
    $ find Movies
Movies
Movies/the_odyssey.mkv
$ find . -name "*.mkv"
./Movies/the_odyssey.mkv
$ find Movies Downloads -type f
Movies/the_odyssey.mkv
Downloads/supergirl.mp4
$ find ~ -type f -name "*.txt"
/home/alice/watchlist.txt
    • without a filter: the directory and everything inside it
    • -name by name, * means any characters
    • -type f only files, -type d only directories
    • several filters: a result must match all of them
    • the results start with the path you gave: start from ~ (an absolute path) and you get absolute paths
    Common mistake

    find . -name *.mkv

    Without quotes, if the current directory has .mkv files, bash replaces *.mkv with their names before find runs. With one match, find only searches for that exact name; with two, it fails with paths must precede expression.

    Instead: always quote the pattern: find . -name "*.mkv".

    Copy files and directories

    cp

    Why it matters

    Copying, moving, creating and deleting is most of what you do with files. The commands are short, they do not ask for confirmation and rm has no trash: knowing exactly what each one does is the only protection.

    cp [OPTION]... SOURCE DEST # DEST: a new name or a directory
    cp [OPTION]... SOURCE... DIRECTORY # several sources: the last parameter is a directory
    $ cp watchlist.txt /home/alice/backup/
$ cp Movies/the_odyssey.mkv Movies/toy_story_5.mkv backup/
$ cp Movies backup/
cp: -r not specified; omitting directory 'Movies'
$ cp -r Movies/ /home/alice/backup/
    • the source is not changed, a new copy is created
    • without -r, cp refuses to copy a directory
    • -r copies the directory and everything inside it
    Move or rename

    mv

    mv [OPTION]... SOURCE DEST
    mv [OPTION]... SOURCE... DIRECTORY
    $ mv movie.mkv project_hail_mary.mkv  # rename
$ mv project_hail_mary.mkv Movies/  # move into a directory
$ mv supergirl.mp4 michael.mp4 Movies/  # several files
$ mv Movies/ Movies_2026/  # rename a directory
    • renaming is moving: to a new name, in the same directory
    • mv does not need -r: a directory moves together with everything inside
    • if DEST is an existing file, it is overwritten without a question
    Check yourself

    ~/Movies exists. What does mv watchlist.txt Movies do?

    Create directories and files

    mkdir, touch and nano

    mkdir [OPTION]... DIRECTORY...
    $ mkdir Movies
$ mkdir Movies/2026/animation
mkdir: cannot create directory 'Movies/2026/animation': No such file or directory
$ mkdir -p Movies/2026/animation

    -p also creates the missing parent directories and does not complain if they exist.

    touch [OPTION]... FILE...
    nano [OPTION]... [FILE]
    $ touch notes.txt
$ ls -l notes.txt
-rw-r--r-- 1 alice alice 0 Sep 30 14:20 notes.txt
$ nano todo.txt
    • touch makes an empty file (size 0); on a file that exists it only updates the date
    • nano opens a text editor; the file is created when you save: Ctrl + O save, Ctrl + X exit
    Delete, permanently

    rm and rmdir

    rm [OPTION]... FILE... # files, and directories with -r
    rmdir [OPTION]... DIRECTORY... # only empty directories
    $ rm dune_3_teaser.mp4
$ rm trailer1.mp4 trailer2.mp4
$ rmdir Trailers
rmdir: failed to remove 'Trailers': Directory not empty
$ rm -r Trailers/
$ rmdir Watched
    Common mistake

    Relying on a trash

    In the shell there is no trash and no undo: rm deletes permanently. rm -r on the wrong relative path (rm -r ../Movies from the wrong directory) removes a whole tree without a question.

    Instead: run pwd and ls on the same path first, and use rmdir for directories you expect to be empty: it refuses to delete anything else.
